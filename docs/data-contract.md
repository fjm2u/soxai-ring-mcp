# MCPツールとデータ仕様

## ツール

| ツール | 主な引数 | 結果 |
| --- | --- | --- |
| `get_health_data` | `kind=daily`、期間、`metrics?`、`limit?`、`offset?` | 測定値・指標の定義・欠測情報・次ページの引数 |

`?` は省略可能です。初回は `get_health_data` の `metrics` を省略して取得します。結果の `available_metrics` に利用できる指標・単位・説明と観測件数が含まれるため、専用の確認ツールは不要です。

- 日付指定：`start_date`〜`end_date`（両端を含む）。`days` は終了日から遡る日数で、`start_date` と併用しません。終了日を省略すると日本時間の昨日です。
- 日時指定：`start_datetime` と `end_datetime` を必ず一緒に指定します。`hours` は現在から遡る時間数で、日時指定と併用しません。
- `kind=daily` では日付・`days`、`kind=intraday` では日時・`hours` を使います。異なる種類の期間引数は混在できません。
- 読み取り結果は `status: ok | no_data` と解決済みの `range` を返します。`no_data` は対象期間に測定行がない状態であり、接続エラーではありません。`ok` はデータの完全性・品質を保証しません。

例：直近48時間は `get_health_data({"kind":"intraday","hours":48})`。日次30日は `get_health_data({"days":30})`。平均・推移・相関は取得したデータをAI側で分析します。

本人確認はOAuth接続時に行います。データ取得時にAPIへアクセスし、トークンも期限前に更新します。失効時は利用中のアプリのMCP／コネクタ設定からOAuthで再接続してください。

## 取得範囲

| Tool | 期間 | 省略時 |
| --- | --- | --- |
| `get_health_data`（日次） | 1〜90日、両端を含む | 昨日までの7日間 |
| `get_health_data`（時刻別） | 最大48時間、開始を含み終了を含まない | 直近24時間 |

「昨日」は`Asia/Tokyo`を基準に決めます。日付は`YYYY-MM-DD`、詳細日時は`2026-10-01T00:00:00+09:00`のようなUTCオフセット付きISO 8601で指定します。

時刻別データは24時間以内の区間に分けて取得し、時刻順に結合します。各区間の終了時刻は含めず、境界時刻の二重計上を防ぎます。片方の取得に失敗した場合は、部分的な結果を返さずエラーにします。

## 指標

`get_health_data` の `available_metrics` は、指定期間全体で数値を観測できた列名と件数を返します。ページや取得対象の `metrics` で絞り込まれる前の一覧です。対象は次の名前に限定しています。

- `sleep_`・`health_`・`activity_`で始まる列
- `hr`、`hrv`、`spo2`、`steps`、`heart_rate`、`respiratory_rate`、`skin_temperature`、`temperature`

これらは許可する名前であり、APIでの提供を保証する一覧ではありません。識別子を含む名前、自由記述、ファームウェア情報は除外します。
公式[OpenAPI](https://web-api.soxai.site/openapi.json)の対象エンドポイントの定義を、`unit`・`description`として添えます。確認日：2026-10-23。未確認の列は両方`null`です。値の単位変換はしません。取得期間に数値がない列は一覧に表示されません。

`numeric_observations` は数値のある行数、`missing_observations` は取得できた行のうち当該指標が欠測している行数です。行自体がない日は `coverage.missing_dates` で別に返します。

| coverage | 意味 |
| --- | --- |
| `expected_days` | 指定した日次期間の日数。時刻別は`null` |
| `missing_dates` | 行がなかった日付。時刻別は`null`（測定間隔を仮定しない） |
| `first_record` / `last_record` | 期間全体の最初・最後の測定日時。行がなければ`null` |
| `includes_today` | 日本時間の今日を範囲に含むか。含む場合は未完了のデータに注意 |

指標一覧・観測数・coverageはいずれもページ分割前の期間全体に対する情報です。数値があることは有効な測定であることを保証しません。カテゴリ値や全ゼロの行を平均に混ぜず、分析側で定義とデータの品質を確認してください。

## 日付と集計

- 日次の`_time`は公式v2 APIの日付ラベル（当日の00:00:00Z）です。UTCの日付をそのまま使い、`utc_offset_mins`や表示タイムゾーンで前後の日へずらしません。
- 時刻別データは実際の時刻順に並べ、UTCで返します。
- 欠測、非数値、NaN、Infinityは`null`。実測の0は保持します。
- サーバーは平均・変化量の計算、欠測の補間、有効性を推測した値の削除をしません。分析側で対象と除外条件を明記してください。
- 日次データで同じ日付に複数行がある場合は、集計せずエラーにします。

活動量と睡眠を比較する際は、SOXAIの睡眠日の定義を確認して日付を対応させてください。

## ページ分割と上限

取得Toolは1ページ最大500行、構造化JSONで100 KBまで返します。既定の `limit` は100件です。
`next_request` があれば、それを同じツールの引数としてそのまま渡してください。期間は絶対日付・日時に固定され、`hours` の再計算で対象がずれることを防ぎます。最終ページは `next_request: null` です。`next_offset` も返します。
ページごとにAPIを再取得するため、同期中はデータが変わる場合があります。分析に必要なページを揃え、期間と観測件数を確認してください。

指標を明示指定する場合は最大32件です。省略時は利用できる全数値指標を返し、行数とJSONサイズでページ分割します。
`health_T`や`health_hr_dB`など、大文字を含むAPIの指標名もそのまま扱います。
SOXAIの測定データ応答は受信中に4,000,000バイトを上限として検査し、20,000行を超えるデータも拒否します。
時刻別の分割取得では、結合前の累計も20,000行・JSON再エンコード後4,000,000バイトに制限します。
HTTP通信には1リクエストあたり15秒のタイムアウトを設定し、自動再試行はしません。

## アクセス範囲

対象UIDはOAuth接続時にSOXAIで確認した本人のUIDに固定します。レスポンスのUIDが欠落・不一致なら全体を拒否します。
この制限はAPIトークン自体の権限を変更しません。組織ユーザーの列挙や生センサーデータ取得は提供しません。
詳しくは[セキュリティとプライバシー](../SECURITY.md)を参照してください。

## エラー

ツール処理の失敗は `isError: true` と `error: {code, action}` を返します。`action` は次に取る操作です。
入力スキーマに合わない型・値・未定義の引数はMCP SDKの入力検証で拒否します。

| コード | 対処 |
| --- | --- |
| `INVALID_RANGE` / `INVALID_DATE` / `INVALID_DATETIME` | 期間の組み合わせ・上限・形式を修正 |
| `METRIC_UNAVAILABLE` / `INVALID_METRICS` | 同じ期間の指標一覧から選び直す |
| `INVALID_PAGE` | `next_request` を使用するかページ引数を修正 |
| `AUTHENTICATION_REQUIRED` / `AUTHENTICATION_FAILED` | MCP／コネクタ設定で接続・再接続 |
| `RATE_LIMITED` / `UPSTREAM_UNAVAILABLE` / `UPSTREAM_ERROR` | 時間を置いて再試行。再ログインを繰り返さない |
| `RESPONSE_TOO_LARGE` | 期間を短くする。返却サイズの場合は指標も絞る |
| `UID_MISMATCH` / `UNSUPPORTED_RESPONSE` | データを解釈せず運用者に確認 |

エラーには認証情報・API応答本文・例外の詳細を含めません。
